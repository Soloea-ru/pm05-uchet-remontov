# Методика тестирования и критерии качества

Этап 11 индивидуального задания ПМ.05. Объект проверки — панель диспетчера СвязьСервис: вход и роли, CRUD заявок и справочников, фильтры, пагинация, CSRF, хеш пароля, ошибки, журнал действий.

Автотесты — основной прогон. Ручная таблица ниже повторяет те же сценарии в форме бланка (шаг → ожидаемый результат → факт), чтобы её можно было перенести в презентацию.

## Как проверяем

1. **Модульно.** Валидаторы форм (`app/validators.py`) без HTTP.
2. **Интеграционно.** Flask test client, временный SQLite через `SQLALCHEMY_DATABASE_URI`. Живой MySQL для автотестов не нужен: те же модели SQLAlchemy, что и в рабочем подключении.
3. **Конфиг.** Строка подключения по умолчанию — `mysql+pymysql://…`, не SQLite. Это закрывает требование бланка «CRUD в MySQL» на уровне рабочего запуска.
4. **Критерий прохождения кейса.** Фактический ответ совпал с ожидаемым, стек Python на экране не показан, запись в базе (где это заявлено) совпадает с экраном.
5. **Критерий прохождения прогона.** `python -m unittest discover -s tests -t . -v` завершается без ошибок. Проваленный кейс либо чинится, либо явно помечается в таблице как «не пройден».

Команда:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -v
```

На Linux / macOS: `python -m unittest discover -s tests -t . -v`.

Прогон этой версии: **2026-11-13**, 23 теста, OK, 14 с.

## Критерии качества и надёжности

| Критерий | Как считаем выполненным |
| --- | --- |
| Вход и роль | Без сессии `/admin` уводит на вход. Абонент получает 403. После выхода старая ссылка на панель не открывается. |
| CRUD | Создание, изменение и удаление заявки и справочника видны в списке и в таблице SQLAlchemy. Занятый справочник не удаляется. |
| Фильтр и пагинация | Фильтр сужает выборку. Страница 2 списка заявок и журнала содержит другие записи, чем страница 1. Пустой фильтр показывает пустое состояние, а не ошибку. |
| CSRF | POST без токена — 400 и страница «Запрос устарел». С токеном операция проходит. |
| Пароль | В `users.password_hash` только PBKDF2-SHA256, открытый пароль не хранится и не отдаётся в HTML. |
| Ошибки | Неверный пароль, пустая форма, 403, 404, сбой базы — понятная страница `error.html` или сообщение у поля, без traceback. |
| Журнал | Вход, создание, изменение и удаление диспетчера пишутся в `admin_actions` и видны на `/admin/journal`. Абонент журнал не видит. |
| Вывод | Данные из базы экранируются шаблоном (нет исполнения HTML/JS из полей заявки). |
| Надёжность | Повторный отказ CSRF и неизвестный URL не роняют процесс. Справочник с заявками остаётся на месте. Сессия после выхода пустая. |
